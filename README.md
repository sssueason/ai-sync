# ai-sync

**多台电脑之间的自动同步 —— 而且改完真的会生效。**

共享配置改一处，后台按节拍推到各端、渲染成各程序真正读的那个文件，再让该重载的程序自己重载。
配一个托盘图标和一个本地控制台：状态、待办、运行记录一屏可见。**零第三方依赖**（只用 Node 内置模块 + 系统自带调度器）。

> 本仓是**引擎**（通用程序，零个人数据）。你的机器清单与路径放在**实例**里 —— 升级引擎不会动你的实例。
> 发布前有一道零容忍的个人串扫描（用户名 / 机器名 / 私有托管地址 / 绝对路径 / 凭据模式），命中即拒绝发布。

## 声明（先读这一段）

**这是什么**

- 一个**自用向**的同步引擎：为"几台自己名下的电脑之间保持文件和配置一致"而写，不是团队协作工具。
- **引擎 / 实例分离**：本仓只有通用程序；路径、机器名、仓库地址、你的数据全在实例里。
- 入口是**人的**：托盘角标三态（绿/黄/红）+ 控制台一屏结论；命令行只是排查手段。

**这不是什么**

- **不是网盘、不是云服务**：没有中心服务器、没有账号体系。你自备一个（建议私有的）git 远端作汇聚点。
- **不是实时同步**，也不是 Syncthing / Dropbox 那一类块级同步的替代品：走的是**按节拍的 git 同步**
  （默认 5 分钟一轮），按**文件**合并。
- **不是免配置产品**：新机器仍要按 `docs/SETUP.md` 走一遍、并准备一个 git 远端。
- **不承诺无冲突并发编辑**：同一文件的并发修改按"先到先得 + 败者另存侧车"处理，详见下面的「局限性」。

**你的数据在哪**

| | 放什么 | 谁持有 |
|---|---|---|
| **引擎**（本仓） | 通用程序、文档、示例 | 公开，可随时删，删了不影响你的实例 |
| **实例**（你自己的私有仓） | `sync/instance.json`（通用设置）· `sync/machines/<机器>.json`（**唯一的绝对路径来源**）· 你同步的那些文件 | 只有你 |

**安全边界**

- 引擎**会**做：读写实例里**声明过**的路径；改由渲染器生成的那几个 live 配置文件；注册/注销它自己的计划任务；按配置重启"自己说空闲"的程序。
- 引擎**不会**做：碰未声明的路径；`git push --force`；自动替你裁决冲突（冲突一律**另存侧车，绝不静默覆盖**）。
- 对端机器建议只给**只读**凭据 —— 代码面的提交权可以只留在主控机（`governance.homeMachine`）。

**维护状态与许可**

- 单人业余项目：**无 SLA、无兼容性承诺**。配置结构和工具行为会随实际使用继续变（有版本号，但不保证向后兼容），升级前先看 `docs/MIGRATIONS.md`。
- MIT。**自担风险**：它会自动改写本机配置文件、并按需触发程序重启，请先在你自己的环境里试。

## 亮点

| 亮点 | 具体是什么 |
|---|---|
| **假绿防线（第一原则）** | 任何"找不到 / 跳过 / 降级 / 不可判定"都必须留信号 —— 非零退出码，或写进状态被巡检报出来。**恒真的检查不算控制**：每加一条自检都要先用故障注入证明"改坏它会亮红"。这条不是口号，是这项目里绝大多数设计取舍的来源。 |
| **单一源 + 渲染器** | 程序读的 live 配置永远由渲染器生成，**不手改**（有漂移检查）。每条规则只留一份实现，机器专属值只有一个来源。 |
| **先看后做** | 会改本地数据的动作默认只报告，`--apply` 才动手，且动手前把计划原样打出来。 |
| **每轮自愈** | 节拍对账、幂等应用、一次性迁移的 `check()` 都由 tick 每轮跑：改了配置下一轮自动生效，被人改回去也会被发现。 |
| **跨机互见** | 心跳里带引擎版本与落后提交数：控制台能直接看出"谁掉队了""谁还在跑旧代码"，而不是等出事后各端互猜。 |
| **出事有档案** | 条件触发的**自包含诊断包**（同指纹去重）：把判定所依据的全部事实固化成一份可离线阅读的文件。 |
| **不打断干活** | 要不要重启由**应用自己**回答（引擎不硬编码分类表）；交互式程序只提醒，不擅自重启。 |
| **文本卫生门禁** | BOM / 行尾 / 残留冲突标记 / "机器本地文件被提交"逐条检查，同一份规则既当每轮巡检、也当发布闸门。 |
| **只读分诊（可选）** | 免费模型只做**建议**：事实走附件、输出固定枚举、不产生命令、不执行、无写权限；默认需显式配置才启用。 |

## 局限性（同样请读完）

| 局限 | 说明 |
|---|---|
| **验证范围很窄** | 只在 **3 台真机**（2×Windows 11 + 1×macOS）长期跑过，量级约 2.5 万文件。**Linux 没有安装器**：node 工具能跑，调度要自备 systemd/cron。Windows Server / 域环境 / 多用户快速切换**都没验证过**。 |
| **不是实时同步** | 按节拍的 git 合并（默认 5 分钟）。别指望"这边一存那边就出现"。 |
| **同一文件并发改没有好解法** | 冲突按"先到先得 + 败者另存 `<名>.local-<机器>-<日期>.<扩展>`"处理：**两版都在**，但需要人来看一眼。这不是 CRDT。 |
| **删除会传播、没有回收站** | 同步语义就是 git 的语义。误删防线（快照备份）在项目里是**另外一层**，不在本仓 —— 不自备备份就等于没有防线。 |
| **云盘镜像（可选）是单向的** | 只增不删、不保证与源**逐字节**等价；它是"给云盘一份只读副本"，**不要在镜像里编辑**（会被下次覆盖，且不回流）。 |
| **没有中心服务与账号体系** | 汇聚点是你自己的 git 远端；对端权限得你在托管平台侧自己约束（本仓只提供第二道闸门）。 |
| **调度依赖系统计划任务 / launchd** | 机器关机、睡眠时不跑，恢复后补跑；它不是常驻守护进程。 |
| **macOS 托盘要自己编译** | 菜单栏 App 是 Swift，需要 Xcode CLT；没有签名后的安装包，也没有 Windows 安装向导之外的分发形式。 |
| **可选分诊会把日志片段发给第三方模型** | 默认需显式配置才启用，可随时关掉；但它确实是一条出网路径，介意就别开。 |
| **接口会变** | 单人维护、无 SLA：配置结构、工具参数、断言名都可能改（断言名会变，是因为"名字必须描述它真正在断言的东西"）。 |

## 三分钟上手

1. **装**：照 [`docs/SETUP.md`](docs/SETUP.md) 走一遍（复制粘贴命令，不需要懂原理）。
2. **看图标**：右下角 / 菜单栏出现循环双箭头。角标 = 状态：🟢 正常 · 🟡 有提醒（不影响同步）· 🔴 要处理；悬浮显示"最后同步"与"有没有要你做的事"。
3. **首次对齐**：双击图标打开控制台 →「首次对齐」按 ① 检查 → ② 看结论 → ③ 执行。看到"已经对齐"就接好了。

之后不用管它。不放心时打开控制台看「总览」。

| 我想…… | 去哪里 |
|---|---|
| 改同步节拍 / 加减同步的文件夹 | 控制台 →「设置」 |
| 不让某个程序的配置被自动改 | 控制台 →「适配器」→ 取消勾选 |
| 看昨天到点跑了什么、失败原因 | 控制台 →「运行记录」 |
| 立刻同步一次，不等下一轮 | 托盘右键 →「立即同步一次」 |
| 看到"引擎可更新（落后 N）" | 托盘右键 →「检查并更新引擎」；机制见 [`docs/OPERATIONS.md`](docs/OPERATIONS.md) §10 |

排障顺序：控制台「总览」的 `FAIL` 行（写了原因）→「运行记录」末行备注 → [`docs/TROUBLESHOOTING.md`](docs/TROUBLESHOOTING.md)；
要弄清"为什么这么判"，看自动生成的诊断包 `sync/reports/ops-bundle-*.md`（见 [`docs/DIAGNOSTICS.md`](docs/DIAGNOSTICS.md)）。

## 架构

```
引擎（本仓，公开、零个人数据）
  tools/sync-tick.mjs        每轮：pull → 渲染 → 收敛 → 推送 → 写状态
  tools/sync-converge.mjs    变更 → 分类 → 谁该重载
  tools/sync-status.mjs      全队状态 + 断言表（控制台「总览」的数据来源）
  tools/sync-doctor.mjs      体检（配置 / 适配器 / 调度 / 仓库 / 卫生）
  tools/sync-schedule.mjs    配置里的节拍 → 平台调度（不一致自动重排）
  tools/sync-hygiene.mjs     文本卫生门禁（BOM/EOL/冲突标记/机器本地文件）
  tools/sync-migrate.mjs     一次性迁移（幂等、可重入、可打印计划）
  tools/sync-apply.mjs       幂等应用（把"拉下来"变成"真的生效"）
  tools/sync-ops-bundle.mjs  诊断包    tools/sync-triage.mjs  只读分诊（可选）
  tools/lib/commit-guard.mjs 提交前守卫（单一实现）
  adapters/{producers,owners}/*.json   声明式接入任意程序
  apps/sync-console/         本地控制台      apps/sync-tray/  托盘 / 菜单栏
  install/                   注册平台调度（Windows 计划任务 / macOS launchd）

实例（私有，你的数据）
  sync/instance.json · sync/machines/<机器>.json · sync/local.machine
  sync/apply-spec.json · sync/migrations/
```

**设计原则**（改代码前先看这几条）

1. **单一源 + 渲染器**：live 配置由渲染器生成，不手改；机器专属值只放 `machines/<机器>.json`。
2. **判定权归应用自己**：要不要重启由应用回答，引擎不硬编码分类表。
3. **假绿防线**：跳过 / 降级 / 不可判定必须留信号；恒真的检查不算控制。
4. **先看后做**：会改本地数据的动作默认只报告，`--apply` 才动手。
5. **同一处规则只留一份实现**：PS / node / bash 三侧读同一份规则文件，避免慢慢漂移。
6. **零第三方依赖**：只用 node 内置模块 + 系统自带调度器。

## 平台要求

| | 要求 |
|---|---|
| Windows | PowerShell 7（`pwsh`）+ Node ≥ 18 + git |
| macOS | Node ≥ 18 + git +（跑 `.ps1` 工具链时需 `pwsh`）+ Xcode CLT（编菜单栏 App 用） |
| Linux | Node ≥ 18 + git（引擎工具是 node，能跑；调度需自备 systemd/cron，本仓未提供安装器） |

## 卸载

1. 停调度：Windows `schtasks /delete /tn ai-sync-tick /f` 与夜间任务（默认 `ai-sync-mirror`，若在
   `cloudMirror.taskName` 改过名就用那个名字）；macOS `launchctl bootout gui/$(id -u)/<label>`。
   也可以让安装器来做：`node install/install.mjs --instance <实例根> --unregister`。
2. 停界面：托盘右键 →「退出」；控制台 `node apps/sync-console/server.mjs --stop`。
3. 跨端状态分支可留可删：`git push origin --delete sync-state`。
4. 引擎目录可以直接删 —— 你的实例和数据都不在里面。
