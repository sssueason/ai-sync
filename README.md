# ai-sync — 多台电脑之间的自动同步（含"改完就生效"）

**它做什么**：你在几台电脑（Windows / macOS / Linux）上共用一些文件和配置。装了它之后，改动会在后台自动传到其他机器上，
相关的程序也会自动读到新配置 —— 不用再记得"先 pull、再重启那个软件"。

**你会看到的东西**：一个托盘图标（Windows 右下角 / macOS 顶部菜单栏），双击打开一个本地网页（控制台），
里面写着"现在同步到哪一步、有没有要你处理的事"。

> 这个仓库是**引擎**（通用程序，里面没有任何人的路径、仓库名、机器名）。
> 你自己的机器清单和路径放在**实例**里（默认 `sync/instance.json` + `sync/machines/<机器名>.json`）。
> 升级引擎不会动你的实例。

---

## 三分钟上手

1. **装**：按 [`docs/SETUP.md`](docs/SETUP.md) 走一遍（复制粘贴命令，不需要懂原理）。
2. **看图标**：右下角出现循环双箭头 🔄。右下角小角标 = 状态：<br>
   🟢 绿圆 = 一切正常 · 🟡 黄三角 = 有提醒（不影响同步）· 🔴 红方块 = 有问题要处理。<br>
   鼠标悬浮上去会显示两行：最后同步时间 + 有没有要你做的事。
3. **打开控制台**：双击图标（或右键 →「打开控制台」）。第一次进「**首次对齐**」页，按顺序点：**① 检查 → ② 看结论 → ③ 执行**。
   看到"已经对齐"就说明这台机器接好了。

之后就不用管了。不放心的时候打开控制台看「总览」。

## 装好之后的日常

| 我想…… | 去哪里 |
|---|---|
| 改多久自动同步一次 | 控制台 →「**设置**」→ ③ 同步间隔 |
| 不想让某个程序的配置被自动改 | 控制台 →「**适配器**」→ 取消勾选它 |
| 再加一个要同步的文件夹 | 控制台 →「**设置**」→ ② 要同步哪些文件夹 |
| 换同步空间目录 / 关掉云盘镜像 | 控制台 →「**设置**」→ ①（留空 = 只用 git 同步） |
| 看昨天到点跑了什么、有没有失败 | 控制台 →「**运行记录**」 |
| 新机器第一次接进来 | 控制台 →「**首次对齐**」（先检查，再执行） |
| 看到"引擎可更新（落后 N 个提交）" | 按控制台顶部横幅给的命令 `git -C <引擎根> pull`；细节见 [`docs/OPERATIONS.md`](docs/OPERATIONS.md) §10 |
| 只想立刻同步一次，不等下一轮 | 托盘右键 →「立即同步一次」 |

**一句话原则**：所有设置都在控制台里点，不需要命令行；控制台里能改的东西，说明文字都写了"改了会发生什么"。

## 控制台有哪几页

- **总览**：一屏看清现在什么状态。逐项检查表里 `PASS` 没问题、`WARN` 是提醒、`FAIL` 要处理（"实际"那列写了原因）；
  「其他机器」看谁掉队了；「需要你做的事」是自动同步做不了、必须人工处理的。
- **设置**：同步什么、多久同步一次。四步走完即可。
- **适配器**：让哪些程序的配置跟着自动更新。每项都能单独关掉（关掉后它的文件保持原样，不会被改）。
- **首次对齐**：新机器跑一次。刻意做成"先看后做"：没点过检查，执行按钮是灰的。
- **运行记录**：每轮一行摘要（时间 / 结果 / 这轮实际做了什么 / 备注），失败行的备注里有原因。

## 同步空间（可选，用云盘备份文档时看）

如果你另外用百度网盘 / OneDrive 这类客户端备份文档，可以把一个目录设成"同步空间"：
本机的指定文件夹会单向刷进去，**只读地**待在云盘里。

- ⚠ **不要在同步空间里直接编辑文件**：改动不会回流本机，还会被下次覆盖。
- 详细说明与目录选择：[`docs/SYNC-SPACE.md`](docs/SYNC-SPACE.md)。

## 出问题了先看哪里

1. 控制台「总览」里有没有 `FAIL` 行 —— 大部分问题那里直接写了原因。
2. 控制台「运行记录」最后一行的备注（失败时里面有诊断）。
3. 还不行：[`docs/TROUBLESHOOTING.md`](docs/TROUBLESHOOTING.md)。

命令行体检（排查时用，平时不需要）：

```bash
node tools/sync-doctor.mjs     # 配置/适配器/调度/仓库 逐项体检
node tools/sync-status.mjs     # 状态总览（= 控制台「总览」页的内容）
```

## 名词小抄

| 词 | 意思（一句话） |
|---|---|
| **tick** | 后台的那次"自动同步"，默认每 5 分钟跑一次 |
| **适配器** | 一条声明："这个程序的配置由同步系统负责生成"。加一个 JSON 就能接入一个新程序 |
| **渲染** | 把共享源里的配置生成到各程序真正读的那个文件里（所以不要手改那些文件） |
| **收敛** | 同步完判断"谁需要重新加载配置"，需要就自动做（不能自动的会列到"需要你做的事"） |
| **对齐** | 首次让本机与云端仓库、同步空间对上；之后由自动同步维持 |
| **同步空间 / 镜像** | 云盘里那份只读副本（可选功能，本文档有时叫它 µ2） |
| **µ1** | 走 git 的那部分同步（共享源 + 配置） |

## 它解决什么问题

| 常见痛点 | ai-sync 的做法 |
|---|---|
| 改了一处共享配置，另外几台要手动 pull、还要重启才生效 | 后台按节拍自动 pull → 渲染 → 收敛（该重载的重载）→ push |
| "到底同步上没有"没人知道 | 托盘角标 + 悬浮两行 + 控制台总览 + 跨机器互见的状态表 |
| 把 A 机器的配置抄到 B，抄漏了或路径写错 | 单一源 + 渲染器：改一处，各端由程序生成，不靠人抄 |
| 新机器要敲一堆命令、容易漏步 | 控制台向导 + 首次对齐 + 安装器 |
| 自动重启打断正在干活的会话 | 重启只走应用自己的"空闲"判断；交互式程序只提醒不重启 |

## 架构（想改代码的看这里）

```
引擎（本仓，公开、零个人数据）
  tools/sync-tick.mjs        每轮：pull → 渲染 → 收敛 → push → 写状态
  tools/sync-converge.mjs    变更 → 分类 → 谁该重载
  tools/sync-status.mjs      全队状态 + 断言表（控制台「总览」的数据来源）
  tools/sync-schedule.mjs    配置里的节拍 → 平台调度（改了配置自动重排）
  tools/sync-align.mjs       首次对齐（先看后做）
  tools/sync-doctor.mjs      体检
  adapters/{producers,owners}/*.json   声明式接入任意程序
  apps/sync-tray/            托盘 / 菜单栏图标
  apps/sync-console/         本地控制台（就是上面那个网页）
  install/                   注册平台调度（Windows 计划任务 / macOS launchd）

实例（私有，你的数据）
  sync/instance.json         节拍、控制台、适配器开关
  sync/machines/<机器>.json  本机路径与集合（唯一的绝对路径来源）
  sync/local.machine         本机标识（不进 git）

平台调度
  Windows 计划任务 ai-sync-tick（每 N 分钟）+ ai-sync-mirror（每晚镜像）
  macOS   launchd ai-sync.tick
```

### 设计原则（为什么这么写）

1. **单一源 + 渲染器**：程序读的 live 配置永远由渲染器生成，不手改；机器专属值放 `machines/<机器>.json`。
2. **判定权归应用自己**：要不要重启由应用回答（如 dsh 的 `restart-guard`），引擎不硬编码分类表。
3. **假绿防线**：任何"找不到 / 跳过 / 降级 / 不可判定"都必须留信号（非零退出码或写进状态被巡检报出来）；恒真的检查不算控制。
4. **先看后做**：会改本地数据的动作默认只报告，`--apply` 才动手，且动手前把计划原样打出来。
5. **不打断用户**：自动重启走空闲门控；交互式程序只提醒。
6. **零第三方依赖**：只用 node 内置模块 + 系统自带的调度器。

## 平台要求

| | 要求 |
|---|---|
| Windows | PowerShell 7（`pwsh`）+ node ≥ 18 + git |
| macOS | node ≥ 18 + git +（要跑 `.ps1` 工具链时需 `pwsh`）+ Xcode CLT（编菜单栏 App 用） |
| Linux | node ≥ 18 + git（引擎工具是 node，能跑；调度需自备 systemd/cron，本仓未提供安装器） |

## 卸载

1. 停调度：Windows `schtasks /delete /tn ai-sync-tick /f` 与 `schtasks /delete /tn ai-sync-mirror /f`；
   macOS `launchctl bootout gui/$(id -u)/ai-sync.tick`
   （或让安装器来做：`node install/install.mjs --instance <实例根> --unregister`）
2. 停界面：托盘右键 →「退出」；控制台 `node apps/sync-console/server.mjs --stop`
3. 删跨端状态分支（可选）：`git push origin --delete sync-state`
4. 引擎目录可以直接删 —— 你的实例和数据都不在里面。
