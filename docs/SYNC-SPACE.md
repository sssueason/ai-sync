# SYNC-SPACE — 同步空间怎么设（云盘镜像 / µ2）

> 这篇回答三件事：**怎么设**、**为什么不能在同步空间里直接改文件**、**它和 git 那套怎么分工**。

---

## 1. 两条腿：git（µ1）与云盘镜像（µ2）

| | µ1（git） | µ2（云盘镜像） |
|---|---|---|
| 装什么 | 配置、脚本、笔记、代码 | 大体积**文档**（docx/xlsx/pdf/数据表…） |
| 谁同步 | 引擎（pull/push，双向） | 网盘客户端（上传/下载） + 引擎的 seed / tree-sync |
| 能否合并 | 能（git 三方合并） | **不能**（二进制无合并语义）⇒ 靠"属主"约定 |
| 节拍 | 默认 5 分钟 | 默认每天 22:00（可调） |
| 出/入 | 双向 | 出：本机权威目录 → 云端镜像；入：云端镜像 → 本机权威目录 |

## 2. 怎么设（三步）

### 第 1 步：在网盘客户端里选一个**同步文件夹**

- 百度网盘：设置 → 传输/同步 → 选择一个本地文件夹作为同步文件夹（**只能一个根**，官方不支持"路径标注"）。
- OneDrive / Dropbox / 坚果云同理。
- 这个根目录就是后面说的"**同步空间**"。

### 第 2 步：确认它在本机的位置

常见默认位置：

| 平台 | 常见路径 |
|---|---|
| Windows | `<云盘同步根>`、`C:\Users\<你>\BaiduSyncdisk` |
| macOS | `~/BaiduSyncdisk` |
| Linux | `~/BaiduSyncdisk`（看客户端） |

### 第 3 步：把它告诉引擎

在 `sync/machines/<本机id>.json` 里写 `mu2.dest` 与 `mu2.sets`：

```json
"mu2": {
  "dest": "<云盘同步根>",     // ← 同步空间根（**必须是客户端配的那个根**）
  "autoSeed": true,
  "sets": [
    { "id": "keti-text", "source": "<权威目录>", "target": "课题文字" }
  ]
}
```

- `source` = **你的权威目录**（你在这里改文件）。
- `target` = 镜像里对应的子目录（相对 `dest`）。
- 一台机器可以有多个 set；多台机器的 set **互不重叠**（见第 4 节）。

控制台向导（`node <引擎根>/apps/sync-console/server.mjs` → 「首次向导」）能帮你**挑目录并校验**：
不是 git 仓 ✓、可写 ✓、目录名像不像云盘同步根（只是提示，不强制）。

## 3. 为什么**不要**在同步空间里改文件

镜像目录里的文件是**由各机器 seed 出来的副本**：

- 你在镜像里改一个文件 → 下次**属主**机器 seed 会用它的权威版本覆盖你的改动（你改的没了）。
- 该改动**不会**回流到任何权威目录（它只存在于云端那份镜像里）。
- 对账工具会把它记成 `extra`（"镜像里多出来的东西"），需要人工裁定。

**正确做法**：改**你自己机器声明集合里的权威目录**（`source`），让引擎把它刷进镜像。
需要改**别人的**目录？找属主，或者让属主把你的目录加成他自己的 set（属主负责写）。

> 例外：<机器> 那类"中心机"可以用 `reconcile-mu2.ps1 -PromoteExtra` 把镜像里多出来的文件**单向提升**进权威树（**绝不覆盖已存在文件**）。这是应急通道，不是日常路径。

## 4. 属主与冲突

- **属主模型**：每个 `source` 只有一台机器在写；其它机器只读镜像。这样根本不会冲突。
- 真的两边都改了（或两台机器都声明了同一台目录）：`tree-sync` 做三方比较，
  **mtime 新者胜**，**败者另存为 `<名>.local-<机器>-<日期>.<扩展名>`**，放在原文件旁边。
  **绝不删除、绝不静默覆盖** —— 你丢不了数据，但需要人看一眼（`sync-status` 会把它报成待办/冲突）。
- 冲突文件属于"看过就能删"的临时物：确认哪份是对的之后，把侧车删掉即可。

## 5. 节拍

- 默认**每天 22:00**（`instance.json` 的 `cloudMirror.schedule`）。
  ```json
  "cloudMirror": { "enabled": true, "schedule": { "mode": "dailyAt", "times": ["22:00"] } }
  ```
- 也可以按间隔：
  ```json
  "schedule": { "mode": "interval", "intervalMinutes": 60 }
  ```
- 改完**不用重装**：下一轮 tick 会按新的到期时间跑（`state.mirror.nextDueAt` 可在状态 JSON 里看）。

⚠️ 两个现实约束（别怪引擎）：

1. **节拍只管"投放/拉回"**：真正传上/传下由网盘客户端做，它慢你就慢。
2. **客户端没登录/没运行**时镜像不会更新；引擎照常把文件放进镜像目录，等客户端醒过来再传。

## 6. 永远不要放进同步空间的东西

- `.git` 目录（云盘会破坏它）
- 数据库文件（`*.db`、`*.sqlite`）、密钥（`*.pem`、`*.key`）、凭据
- 原始科研数据（`.dcm` / `.gz` / `.bam` / `.tif` / `.raw` / `.fcs`）
- Office 锁文件与临时文件（`~$*`、`*.tmp`）—— 引擎的过滤清单已排除，但你自己拷贝时也别带进去

引擎的 `doctor` 与 `doctor-lite` 会检查这些（"越界即停"）。
